**判据**：MCV 偏差 ≤ 0.005 m/s（PCV 与 mpp 为诊断量，不作判据）
**详细报告**：[IRON_GATE_20260913.md](IRON_GATE_20260913.md)

| mpp 相对误差中位数 | 0.080% |
| ASan 内存错误 | **0** ✅ |

**残差归因**：沙箱环境 Python 用 OpenCV 5.0.0（PyPI wheel）、C++ 用自建 4.10.0，
`goodFeaturesToTrack` / `calcOpticalFlowPyrLK` 跨大版本实现差异 → 特征点集不同 →
LK 观测序列微分叉。证据：偏差集中在 0.005–0.03 小区间，而不经光流的 mpp 两端一致到 1e-6。
**建议在两端统一 OpenCV 版本的环境（如用户 WSL2）复跑。**

**闸门未绿 → 按铁律未启动 Android NDK 交叉编译。**

### 为什么 v0–v6 的 baseline 是「错误残渣」

旧 `validation/reports/cpp_baseline/` 是**卡尔曼死锁 + 级联平滑时期**产生的。
例：`110kg_0.71_0.73.mp4` 旧 baseline 切出 3 个假 rep（0.381/0.517/0.804），
真值只有 2 个（0.71/0.73）。拿正确的新代码去比对错误的旧 baseline，必然全盘失败。
故 2026-09-13 用现行正确流水线全量重建。
