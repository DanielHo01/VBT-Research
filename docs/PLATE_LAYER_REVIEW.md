# 杠铃片层技术路线复核（PLATE LAYER REVIEW）

> 日期: 2026-09-10 · 基于 34 视频全量基准 + 专项诊断实测数据

---

## 一、结论先行

**问题不在"检测器不够好"，而在"我们把一个跟踪问题当成了逐帧检测问题"。**

- barbell_v4 在合格帧上的置信度高达 **0.74–0.92**，检测能力本身不是瓶颈（40 帧里能检出 6 次以上的帧占 89%）。
- 真正拖垮 RMSE 的是三个架构问题：
  1. **没有身份锁定** —— 每帧独立重检、取 top-1，帧间可能在"杠铃片 / 架子上的片堆"之间切换；
  2. **标定混入了别的片** —— scale 由"全视频所有 ratio≤1.4 的检测"的中位高度算出，多片环境直接污染；
  3. **没有运动合理性约束** —— 单帧 200px 跳变被当成真实运动，产生 ±5.5 m/s 的速度尖峰，落进 rep 窗口就把 MCV 拉高。

**路线修正方向**：初始化锁定一块片 → 刚体跟踪（亚像素）→ 检测器只做丢失恢复。这与 QwikVBT（手动点片后跟踪）、Metric（自动检测后跟踪）、以及开源 [amadeu01/image-tracker](https://github.com/amadeu01/image-tracker)（ZNCC 双模板刚体跟踪）的做法一致。

---

## 二、当前实现（as-built，如实记录）

```
每帧 → YoloPlateDetector.detect()（top-1）
     → 圆形度门控 ratio ≤ 1.4 + conf ≥ 0.25（不合格则丢弃该帧检测）
     → TargetAssociator（状态机 INIT→ANCHORING→TRACKING→LOST）
     → α-β 外推补 1-3 帧 → median_filter(3) → savgol(5,2)
     → segment_reps（peak→trough 分段）
     → mCV = 窗口内正速度均值
```

关键代码事实（`algorithms/pipelines.py`、`algorithms/common.py`）：

| 位置 | 事实 | 后果 |
|---|---|---|
| `detect()` | 只取 top-1 检测 | 多片时可能逐帧切换目标 |
| `TargetAssociator.process_frame` TRACKING 分支 | `dist` 超阈值时**仍然 `is_valid=True`** | 距离门控形同虚设，不提供身份保护 |
| `_parse_video_associator` 标定段 | `heights[ratio≤1.4 & conf≥min_conf]` 取中位数 | 混入架子上/背景里的片 → scale 偏差可达 30% |
| `segment_reps` | peak→trough 各自配对，无去重 | 同一次动作可切出**多个重叠 rep** |
| 全流程 | 无非物理速度过滤 | 跳变产生的 5 m/s 尖峰直接进 MCV |

## 三、实测证据（34 视频 + 专项诊断）

### 3.1 全量基准（barbell_v4 + associator，修复双重 sigmoid 后）

| 指标 | 数值 |
|---|---|
| RMSE mean / median | **0.273 / 0.185 m/s** |
| 可评估视频 | 28/34（4 无片：20kg 空杆等；2 标定成功但未分出 rep） |
| 视频级 RMSE ≤ 0.10 | 6/28（21%） |
| rep 数量完全匹配 | 11/30 |
| 漏检 rep / 幻影 rep | 14 个视频漏检 / 5 个视频幻影 |

### 3.2 片层专项诊断（4 个代表视频）

| 视频 | 检测率 | 每帧检测数 | **多片帧** | 轨迹簇 | **跳变率** | 标定可用帧 | h 范围 |
|---|---|---|---|---|---|---|---|
| 110kg_0.71_0.73（好，RMSE 0.07） | 99% | 1.25 | 25% | 5 | 1% | 97% | 198–212 |
| 102.5kg_0.53_0.38（偏差 +0.77） | 93% | 1.78 | **74%** | 37 | 4% | 74% | **137–178** |
| 110kg_0.61_…_0.38（幻影 rep，RMSE 1.19） | 83% | 1.32 | 45% | **126** | **8%（p95=207px）** | 29% | 143–171 |
| 105kg_0.61_…_0.32（漏检 rep） | 80% | 0.92 | 12% | 52 | 0% | 25% | 167–191 |

**多片帧占 12–74%**：健身房里架子上、地上全是片，逐帧 top-1 必然面临身份歧义。

### 3.3 决定性证据：速度尖峰与 rep 污染

102.5kg_0.53_0.38.mp4 内部速度曲线：

```
帧 165-168: -6.0, -3.8, +3.3, +5.5 m/s   ← 两帧内正负翻转 = 典型目标跳变特征
帧 195-198: -5.6, -3.5, +3.4, +5.5 m/s
|Δy| > 60px 的帧: 9 个（位置 165,167,195,197,525,555,560,567,581）

分段结果（注意窗口重叠）:
  rep 167-284  mcv=0.725  窗口内 max|v|=5.6   rom=52cm
  rep 197-284  mcv=0.579  窗口内 max|v|=5.5   rom=65cm
  rep 227-284  mcv=0.350  窗口内 max|v|=1.2   rom=45cm   ← 三个窗口结束在同一帧
  rep 527-590  mcv=1.072  窗口内 max|v|=5.2   rom=77cm   ← rom 77cm 超过人体深蹲幅度
  rep 557-590  mcv=1.280  窗口内 max|v|=5.2   rom=74cm

GT MCV = [0.53, 0.38] → 预测均值 ≈ 1.23（偏差 +0.77）
```

对照组 110kg_0.71_0.73（RMSE 0.07）：**0 个尖峰、0 个跳变**，ROM 55cm，mcv 0.65/0.63 vs GT 0.71/0.73。

**102.5kg 系列 5 个视频全部高估 +0.27~+0.77，机制就是"跳变 → 尖峰 → 污染 rep 窗口"，不是标定误差**（标定最多造成 ~15–30% 偏差，解释不了 +150%）。

### 3.4 检测器本身的小发现

| 模型 | 普通 resize | letterbox |
|---|---|---|
| barbell_v4 (416) | 0.92 / 0.87 / 0.74 / 0.85 | 0.63 / 0.86 / 0.60 / 0.88 |
| **yolo11_plate (640)** | 0.91 / **0.41** / 0.61 / 0.91 | 0.63 / 0.73 / 0.78 / 0.70 |
| plate_v1 (640) | 0.04 | 0.02 |

- barbell_v4 目前用**普通 resize**（非 letterbox）反而略好 → 说明它就是按这种预处理训的，不用改。
- **yolo11_plate + letterbox 置信度更稳定（0.63–0.78，波动小）**，是没验证过的候选，值得单独跑基准（接入前需先统一预处理）。
- plate_v1 侧视基本失效，确认弃用。

## 四、修正后的路线（方案 A：先锁定、再跟踪）

```
① 初始化（一次）: 自动挑"会随杠铃运动 + 尺寸最大且稳定"的检测作为追踪目标
   （或复刻 QwikVBT 的"用户点一下片"，最稳）
        ↓  锁定：plate_h_px（用于标定）、模板、初始位置
② 逐帧跟踪（刚体，非重检）: 
   运动模型预测搜索窗（匀速） + ZNCC 模板匹配 → 亚像素 y
   模板随光照缓慢更新（双模板防漂移）
        ↓  亚像素轨迹 (t, y)，天然连续
③ 合理性门控（每帧）:
   |Δy| > 物理上限（如 4 m/s × scale / fps）→ 判为异常，用运动模型外推，不更新位置
   尺寸漂移 > 15% → 判为丢失，触发重新检测
        ↓
④ 检测器降级为"恢复机制":
   跟踪丢失 > N 帧且在搜索窗内没有响应 → 跑一次 YOLO
   恢复时只接受"尺寸与锁定 h 一致（±15%）"的检测
        ↓
⑤ 标定: 用锁定片的 h 中位数（全视频稳健估计），
   斜视角时改用椭圆短轴；不再混合其他检测
        ↓
⑥ 分段: 单次动作只产出一个 rep（用峰谷配对+去重+单调区间约束），
   MCV 用平滑后轨迹的解析导数
```

### 预期收益（基于实测推断）

| 修复项 | 针对 | 预期 |
|---|---|---|
| 合理性门控（③） | 102.5kg 系列 +0.27~+0.77、110kg 幻影 rep | 直接消除 5 m/s 尖峰；这批视频的偏差有望回到 ±0.05 内 |
| 身份锁定（①②④） | 39–74% 多片帧、126 个轨迹碎簇 | 消除目标切换；覆盖率提升（跟踪可穿越短暂遮挡） |
| 标定只用锁定片（⑤） | h 范围 137–178 的污染 | scale 稳定到 ±5% 内 |
| 分段去重（⑥） | 重叠 rep、rep 数不匹配（19/30） | rep 计数匹配率显著提升 |
| 漏检 rep（105kg 系列） | 完全遮挡 | 需要模板跟踪 + 运动模型，收益有限，属下一阶段 |

### 不做（明确排除）

- ❌ **先重训检测器**：Phase 1.5 已证明方向错误；检测置信度也显示不是瓶颈。
- ❌ 继续用伪标签扩数据：噪声源不在数据量。
- ❌ 换更大模型：YOLOv8s → 更大模型解决不了身份歧义。

### 保留可选项

- yolo11_plate.onnx（letterbox 预处理）作为跟踪丢失时的恢复检测器候选，跑完基准再定。

## 五、验收标准（每步都要能量化）

| 阶段 | 指标 | 目标 |
|---|---|---|
| 阶段 1：合理性门控 + 标定只用锁定片 | 102.5kg 系列 bias | \|bias\| < 0.05 |
| 阶段 2：身份锁定 + 刚体跟踪 | 全量 RMSE median | < 0.10 |
| 阶段 3：分段去重 | rep 计数匹配率 | > 80% |
| 阶段 4：遮挡恢复 | 105kg 系列漏检 | 从 1/4 rep 提升到 3/4 |

对标：QwikVBT vs Vicon RMSE = 0.01–0.04 m/s（Renner et al., PLOS One 2024）；GymAware 自身误差量级 ≈ 0.02–0.06 m/s。**我们的理论天花板不在模型，而在"跟踪精度 + 标定准确度"**：亚像素跟踪（0.1–0.3px）在 scale≈0.0025 m/px 下等于 0.5mm 定位精度，速度噪声可忽略。
